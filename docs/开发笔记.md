# 开发笔记（逆向结论 / 维护用）

> 这份文件是给维护者的，用户不需要看。面向用户的说明在仓库根目录 `README.md`。

## 0. 环境事实

| 项 | 值 |
| --- | --- |
| 游戏 | Sprocket `0.2.55.5`，Unity **6000.3.21f1**，IL2CPP 元数据 **v39** |
| 加载器 | BepInEx **be.788** + 社区兼容补丁（必须，否则启动黑屏） |
| 插件目标框架 | `net6.0` |
| 编译依赖 | 只需 BepInEx 的 NuGet 包；**但炮弹部分用了强类型 interop**，所以需要先运行一次游戏生成 `BepInEx/interop/*.dll`，再 `-p:InteropDir=<游戏目录>/BepInEx/interop` 编译 |

为什么必须用打过补丁的 be.788：原版 Il2CppInterop 在本作的原生代码上会**匹配错函数**并挂错钩子
（正确目标 `0x4945E0`，它选到 `0x16D540`），导致进程崩溃/黑屏。补丁同时修复了
`Class::Init` 签名匹配与泛型方法调用约定。

## 1. 为什么需要这个模组（游戏原本的散布模型）

* AI 的瞄准误差来自 `FindAndAimAtTargetGunLayerTask.Update()`，随机量乘上
  `ZeroingErrors[已对同一目标开火次数] × maxRangeError × AccuracyModifier`。
* 实测原版 `ZeroingErrors = [1, 0.5, 0.3, 0.2, 0.1, 0.025]` —— **第 6 发只剩首发的 2.5%**，
  于是 AI 会变成"激光"。这是玩家抱怨"精准命中炮塔座圈"的直接原因。
* 实测原版 `maxRangeError = maxVelocityError = 0.1`。
* 该数组的索引**每次调用动态读取数组长度**（`min(count, length-1)`），所以**换成更长的数组 =
  自动延长试射期**（当前版本未暴露此功能，但可做）。
* 对**静止目标**，AI 的瞄准误差只有**一维**（只有"目标位置估计"那一项有效，"目标速度"项恒为 0）
  ⇒ 落点只沿视线前后移动 ⇒ 屏幕上表现为"一条竖线"。**要得到二维散布必须扰动出膛方向。**

## 2. 炮口散布：游戏里有什么、什么不能用

* `ShellProperties.CalculateDispersion(caliber, distance, muzzleVelocity, barrelLength)`
  反汇编后恰好是：
  ```
  dispersion = 500 · caliber · distance / (muzzleVelocity · barrelLength)
  ```
  （常量 25 / 0.5 / 100 / 1000 已从二进制读出）
  **但它是死代码** —— 全工程没有任何调用点；`CannonBlueprint.GetDispersion(range)` 同样无人调用。
* 实战散布在 `DetonationPropellantProjectileFunction.AggregateLaunchInfo()` 里**内联**计算，
  形状与上面相同（∝ 口径/(初速·管长)）但**没有距离项**，且量级极小。
* 因此 `GetRandomAccuracyOffset()` / `GetFireDirection()` 都被**内联**，**打补丁无效**。

**本模组的做法（用户选定的方案 B）**：不调用那个死函数，直接按其形状做比值
（所有常量与单位在比值中约掉）：

```
ratio = (口径/RefCaliber) × (RefBarrelLength/管长) × (RefMuzzleVelocity/初速)
ratio' = ratio > 1 ? 1 + (ratio-1)·LooseSideCompression : ratio   # 只压"较散"一侧
r95    = clamp(AccuracyAt100m × Scale × ratio', Min, Max)
```

**单位（实测）**：口径与管长都是**米**（0.075 / 3.151 对应 75 mm L/42；0.088 / 4.915 对应 88 mm L/56）。

## 3. 补丁点（一共 5 个）

| 方法 | 类型 | 作用 |
| --- | --- | --- |
| `Sprocket.Vehicle.VehicleAIAssemblyStage.AddGunLayerAIs` | Prefix | AI 载具生成时缩放 `maxRangeError/maxVelocityError` |
| `Sprocket.ArtificialIntelligence.GunLayerAI.Step` | Prefix | 尽早触发 `ZeroingErrors` 曲线的写入 |
| `Sprocket.DamageModelling.ProjectileRegister.Launch` | Postfix | ★ 炮口散布 |
| `…IProjectileFactory.Launch`（显式接口实现） | Postfix | 同上；**两个入口都会触发，必须按炮弹 ID 去重** |
| `ProjectileRegister.FixedUpdate` | Prefix | 只回读校验（`[verify]` 日志） |

## 4. 写进炮弹的正确姿势（踩过的坑）

* `ProjectileInstance` 是**含引用字段的非 blittable 值类型**，因此
  `Il2CppReferenceArray<ProjectileInstance>` 的元素是**内联存储**（`ourElementIsValueType == true`，
  步长 = `il2cpp_class_value_size`），而生成的元素包装是**拷贝语义** ⇒ 通过它改字段**不会写回游戏**。
  **必须裸指针直写**：
  ```
  element(i) = pool.Pointer + 0x20 + i × elementSize      # elementSize 实测 = 80 (0x50)
  ```
* 数组布局：`klass(0x0) monitor(0x8) bounds(0x10) maxLength(0x18) vector(0x20)`。
* 用到的字段偏移：

  | 类型 | 字段 | 偏移 |
  | --- | --- | --- |
  | `ProjectileInstance` | `def` | 0x08 |
  | | `ID` | 0x18 |
  | | `velocity` | 0x34 |
  | `ProjectileDefinition` | `Mass` / `Diameter` / `Length` | 0x30 / 0x34 / 0x38 |
  | `ProjectileRegister` | `pool` | 0x38 |

* **自检**：写完记住炮弹 ID，下一帧在 `FixedUpdate` 回读比对，日志打印 `[verify] id=… OK/LOST`。
  同时按 ID 校验（找不到就告警并**自动停用**），避免写错内存。
* 日志 `[gun] caliber=… barrel=… v=… -> ratio=… (compressed …) -> r95(GunData)=…` 每门炮只打一次，
  用来核对单位与标定参考炮。

## 5. 其他已确认的事实

* `GunLayerAI.SetSettings()` 被**内联**，全游戏无人调用；真正写入 AI 设置的是
  `VehicleAIAssemblyStage.AddGunLayerAIs()`（直接字段赋值）。
* `MaxAimOffset = 0.25f` 是编译期常量，运行时改不了。
* `AttackOrderInfo.accuracyModifier` 默认 **1.0**（`AttackOrderStageEvent..ctor` 里写死），
  它被 `CommanderAI.Attack()` 复制进任务的 `AccuracyModifier`，本模组**没有动它**
  （同一任务对象会被压进多门炮的任务栈，简单拦截会重复相乘）。
* `ProjectileLauncherInfo` 只有 `BarrelLength` / `MaxPressure`，**没有发射者信息**
  ⇒ 无法只在 AI 的炮弹上加散布。

## 6. 失效模式与排查

游戏大版本更新后，先看 `BepInEx/LogOutput.log` 里这几行来判断坏在哪一环：

```
Patched ProjectileRegister.Launch (2 entry point(s)) + FixedUpdate … elementSize=80
[verify] id=… OK / LOST          # LOST 或大量 not found ⇒ 池子布局/步长变了
[gun] caliber=… barrel=… v=…     # 单位或字段偏移变了
```

所有钩子都有 `try/catch`，异常时**只停用对应功能**并写日志，不会崩游戏。

## 7. 构建

```bash
./get-bepinex.sh                 # 准备加载器（be.788 + 兼容补丁）到 third_party/
DOTNET_ROOT=<dotnet6> ./build.sh # 需要先运行过一次游戏，才有 BepInEx/interop
./pack.sh                        # 产出 dist/Sprocket.AiDispersion-1.0.0.zip
```

工具链（重建分析环境用）：Cpp2IL `2022.1.0-pre-release.21`；Il2CppDumper 的
`c01ns` v39 分支（Perfare 原版不支持元数据 v39）。
